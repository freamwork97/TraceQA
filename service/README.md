# TraceQA managed service

Node.js 24, Playwright Chromium, SQLite on a persistent volume. `Dockerfile` installs Chromium and OS dependencies. Startup fixes volume ownership then drops to the node user. One replica, one active exploration at a time.

## Railway

- Project: traceqa / c1438a62-5d29-4033-a79e-2cd10bbe6765
- Production: e8afced4-7a08-4c0f-88a1-060f1d43fd98
- Service: traceqa-worker / 76c6021d-4f8f-42b4-a225-6301454caacb
- Volume: /data, 512 MB. Database: /data/traceqa.sqlite.
- Resource limit: 1 vCPU, 1 GB RAM. No guaranteed monthly cost: Railway meters actual usage.
- Runtime: 30 minutes per run, no depth limit. User-selected credit budget also stops a run.

## Secrets and identity

`SERVICE_TOKEN` authenticates server-to-server requests from the Sites gateway. The gateway takes visitor identity only from Sites dispatch and replaces all client-supplied identity and auth headers. Customers never receive the service token or OpenAI key.

Operator must set `OPENAI_API_KEY` in this service's Railway Variables. It is intentionally absent until a real key is supplied. Never commit it or put it in frontend JavaScript. The supported secure key-creation flow failed, so no OpenAI key has been generated by this app.

Sites runtime values: `SERVICE_URL` (Railway HTTPS origin), `SERVICE_TOKEN` (same secret). No browser-side worker configuration.

## Billing

Test-only integration. Live Stripe keys and live webhook events are rejected. Operator configures test `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, a one-time `STRIPE_PRICE_ID` and `CREDIT_PACK_CREDITS`. Webhook URL is the Railway origin plus `/billing/webhook`. Payment completion is credited only on signed webhook confirmation. Returning to success_url never credits an account.

The credit model reserves a user-selected budget. One successfully analyzed new screen per run consumes one credit. Unused reservation is returned at end. AI failures are not charged. Transactions, session deduplication, used-screen keys and restart recovery are persisted in SQLite. Screenshot data is included in the saved run. Commercial price, refunds, taxes and production payment availability remain to be configured before a paid launch.

## Readiness and limits

GET `/health` is public, exposes service/version only, and proves process health. Authenticated GET `/status` reports AI key presence, installed Chromium and payment configuration. Key presence is not proof of API quota or model access. All other internal routes require a service token and a gateway-supplied user ID. The gateway exposes only user endpoints; webhook remains on Railway.

This is a single-instance MVP, not a distributed queue. SQLite snapshots can grow with screenshots. Configure retention and object storage before high-volume use; monitor the 512 MB volume. A restart marks interrupted runs and releases unused holds; it does not resume browser state. DNS checks do not fully prevent rebinding; enforce private-address egress restrictions before accepting untrusted production customers. Login sessions, iframe recursion, manual assertions, production payments and dispute/refund workflows are not included.

`node --test service/test.mjs gateway/test.mjs worker/test.mjs` tests ledger integrity, payment verification, owner isolation, gateway identity, and target policies without incurring AI charges.
