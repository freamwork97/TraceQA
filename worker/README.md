# TraceQA Playwright worker · MVP

Sites 관리 화면에 연결하는 별도 실행 서버입니다. Node.js 22 이상과 Chromium 실행이 가능한 Linux/macOS/Windows 서버가 필요합니다. Sites의 정적 호스팅 안에서 실행하는 코드는 아닙니다.

## 시작

1. `npm install`
2. `npx playwright install chromium` (Linux 시스템 라이브러리가 필요하면 Playwright 공식 설치 안내 참조)
3. `.env.example`을 `.env`로 복사하고 값을 설정합니다.
4. `TRACEQA_TOKEN`에 24자 이상 임의 문자열을 지정합니다. 예: `openssl rand -hex 32`.
5. `TARGET_HOSTS`에 본인이 테스트할 권한이 있는 대상 호스트를 정확히 나열합니다. 하위 도메인도 각각 등록합니다.
6. `ALLOWED_ORIGIN`에 Sites 관리 화면의 출처를 설정합니다.
7. `npm start`
8. 워커 앞에 HTTPS 리버스 프록시를 구성합니다. 관리 화면의 설정에서 HTTPS 주소와 토큰을 입력합니다. 기본 바인딩은 127.0.0.1:8787입니다.

토큰과 AI 키는 소스에 커밋하지 마세요. API는 모든 요청에 Bearer 인증을 요구합니다. URL만 브라우저에 저장하고 토큰은 탭 메모리에 유지합니다. 워커 로그에는 토큰을 출력하지 않습니다.

## AI 분석

`OPENAI_API_KEY`와 이미지 입력 및 JSON 응답이 가능한 `OPENAI_MODEL`을 설정합니다. 기본 모델은 gpt-4.1-mini이며 계정에서 지원하는 모델로 변경할 수 있습니다. AI에 대상 페이지 스크린샷, 제목, 요소 이름 및 위치가 전송됩니다. 민감 정보가 포함되지 않은 테스트 환경을 사용하세요.

AI는 화면명·설명을 제안하고 DOM 대상과 화면을 연결합니다. DOM에 없는 명확한 조작 요소는 영역 좌표를 제안할 수 있습니다. 좌표는 1440×900 CSS 픽셀 기준이며 기기 배율은 1입니다. 좌표 대상은 높은 신뢰도, 화면 경계, DOM 중복, 위험 동작, 클릭 직전 화면 해시를 확인합니다. 화면이 달라지면 클릭을 거부합니다. 이는 오클릭을 줄이는 보수적인 MVP 정책이며 인식 정확도를 보증하지 않습니다.

## 탐색 정책

- 깊이 제한 없는 DFS. 신규 화면 상태를 확인하고 각 대상까지 시작 경로를 재실행합니다.
- URL, 제목, 헤딩, 모달, 선택 상태, 조작 요소, 스크롤 위치로 화면 상태를 구분합니다.
- 읽기 전용: 브라우저의 GET/HEAD/OPTIONS 외 요청은 차단합니다. 일부 검색·GraphQL·SPA는 이 정책으로 동작하지 않을 수 있으며 요청 제외 로그로 남깁니다.
- 같은 Origin만 탐색하며 외부 이동은 차단합니다. 외부 공개 CDN 리소스는 허용합니다.
- 삭제·결제·전송·제출 등 명백한 변경 대상과 달력 무한 생성 동작은 제외합니다. 문구 검사만으로 위험 동작을 모두 알아낼 수는 없으므로 테스트 환경 사용이 필요합니다.
- 스크롤로 추가 콘텐츠를 발견합니다. 무한 피드 전체 완료는 보장하지 않으며 사용자가 중단할 수 있습니다.
- 화면 변화가 없는 클릭은 중복 상태로 기록하며 결함으로 확정하지 않습니다.
- 로그인/폼 입력/인증 상태 업로드, iframe 내부 재귀 탐색, 닫힌 Shadow DOM은 이번 MVP에서 지원하지 않습니다. 새 창은 같은 Origin의 GET URL로 발견 시 큐에 추가합니다. POST·세션 의존 새 창은 제한됩니다.

## 결과 판정

시작 페이지의 HTTP 응답 정상 여부만 자동 통과 판정을 내립니다. 다른 동작의 업무 정상 여부는 요구사항이 없으므로 '검토 필요'입니다. 오류 페이지 문구는 후보로, 직접 확인한 페이지 HTTP 실패는 검증 실패로 기록합니다. 최종 메인 프레임의 HTTP 응답을 추적하며, 하위 API 요청의 업무 의미 분석과 요구사항 기반 assertion은 후속 구현 대상입니다.

## 운영 한계

이 버전은 단일 워커, 동시 1개 실행, 메모리 저장입니다. 기본 24시간 후 종료된 기록을 삭제하며 재시작 시 유실됩니다. 캡처는 인증된 API에서 이미지 데이터로 반환합니다. 페이지 수가 많으면 응답·메모리가 커지므로 장시간 운영에는 DB, 객체 저장소, 작업 큐와 증분 조회 API가 필요합니다. 일시정지는 다음 작업 경계에 적용되며 진행 중 네트워크 작업이 즉시 취소되지는 않습니다. 중단 후 서버 재시작을 넘는 재개는 지원하지 않습니다.

SSRF 방어는 허용 호스트·공개 IPv4 확인·요청별 검사·Origin 제한을 적용합니다. DNS 검사 후 브라우저 연결 사이의 재바인딩 위험을 완전히 제거하지 못하므로 운영 서버의 방화벽/프록시에서도 사설·메타데이터 주소를 차단해야 합니다. 이 워커를 인터넷에 무인 운영하기 전 실행 격리와 네트워크 정책을 구성하세요.

## API

- `GET /health` → `{service,version,ai,mode}`
- `POST /runs` body `{url}` → 실행 생성
- `GET /runs/:id` → 실행 상태와 수집 결과
- `POST /runs/:id/pause`, `/resume`, `/stop`

헤더: `Authorization: Bearer <TRACEQA_TOKEN>`.

## 검증

`npm test`로 대상 주소 정책, 상태 구분, 데이터 변경 제외 규칙을 확인합니다. 실제 대상 탐색과 AI 응답은 서버·Chromium·AI 키 설정 후 별도 통합 검증이 필요합니다.
